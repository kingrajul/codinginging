📖 What is the Referer Header?

When you click a link or load a resource, the browser includes a Referer request header containing the URL of the page you came from. (Note: "Referer" is a historical misspelling of "Referrer" — it stuck.)

Modern URLs often carry sensitive data in query strings:

https://app.example.com/reset-password?token=eyJhbGciOiJIUzI1NiJ9.abc123
https://shop.example.com/checkout?promo=SECRET50&user=12345
https://portal.example.com/patients?id=98765&ssn=123-45-6789

Without a Referrer-Policy header, all of this leaks to every third-party resource the page loads (analytics, CDN scripts, embedded images, ad networks).

🔴 The Attack — Token and Session Leakage

  1. 1User receives a password-reset email with a link:
    https://app.example.com/reset?token=abc123secret
  2. 2User visits the link. The page loads a Google Analytics script, a CDN-hosted font, and an ad pixel — all third-party.
  3. 3Each of those requests includes:
    Referer: https://app.example.com/reset?token=abc123secret
  4. 4The third-party servers (and anyone who can read their logs or intercept the traffic) now have the password-reset token.
  5. 5Attacker uses the token to reset the victim's password before they finish the flow.

Real-world examples of this class of vulnerability:

  • OAuth authorization codes leaked via Referer to third-party iframes.
  • API keys in URL parameters exposed to analytics platforms.
  • Medical record IDs leaked from patient portals to ad networks.
  • CSRF tokens visible to third parties, reducing their effectiveness.

✅ The Fix — Referrer-Policy

The Referrer-Policy header controls how much of the URL is included in the Referer header for outbound requests.

Recommended safe policy:

Referrer-Policy: strict-origin-when-cross-origin

This sends the full URL only on same-origin requests (useful for your own analytics), and only the origin (no path or query string) for cross-origin requests.

Policy comparison:

PolicySame-origin sendsCross-origin sendsSafe?
no-referrer nothingnothing ✓ safest
strict-origin-when-cross-origin full URLorigin only ✓ recommended
same-origin full URLnothing ✓ good
origin-when-cross-origin full URLorigin only (even on HTTP→HTTP) ✓ acceptable
unsafe-url full URLfull URL ✗ dangerous
(no header — browser default) full URLfull URL (usually) ✗ this site's current state

In Nginx:

add_header Referrer-Policy "strict-origin-when-cross-origin" always;

You can also set it per-page with an HTML meta tag (no server access needed):

<meta name="referrer" content="strict-origin-when-cross-origin">
