⚠️ Security Headers Demo

EDUCATIONAL USE ONLY

This site intentionally has no HTTP security headers. Each page below demonstrates a specific attack and how the right header prevents it.

🚨 Heads Up

This server is running without any protective HTTP headers. Open DevTools → Network → select any request → inspect the Response Headers tab to confirm. Never deploy a configuration like this in production.

Missing Headers & Their Exploits

💉

Cross-Site Scripting (XSS)

Content-Security-Policy

Injected scripts run freely — steal cookies, redirect users, deface the page.

● HIGH SEVERITY
🖱️

Clickjacking

X-Frame-Options

Attackers embed this page in an invisible iframe to trick users into clicking hidden buttons.

● HIGH SEVERITY
🎭

MIME-Type Sniffing

X-Content-Type-Options

Browser ignores declared Content-Type and executes files as HTML or JavaScript.

● MEDIUM SEVERITY
🔓

SSL Stripping / Protocol Downgrade

Strict-Transport-Security

Without HSTS, attackers on the same network can silently downgrade HTTPS → HTTP.

● HIGH SEVERITY
🔗

Referrer Information Leak

Referrer-Policy

Full URL (including tokens, search terms, user IDs) is sent to third-party sites.

● MEDIUM SEVERITY
📷

Dangerous Feature Access

Permissions-Policy

Scripts or iframes can silently access camera, microphone, and geolocation.

● MEDIUM SEVERITY

🐳 Running This Demo Locally

  1. Ensure Docker and Docker Compose are installed.
  2. From the project root run: docker compose up -d
  3. Open http://localhost:8080 in your browser.
  4. Open DevTools → Network tab, click any request, and inspect Response Headers — notice the complete absence of security headers.
  5. Navigate each demo page to see the attack and the fix side-by-side.
  6. To stop: docker compose down
For educational purposes only — do not deploy this configuration in any real environment.
