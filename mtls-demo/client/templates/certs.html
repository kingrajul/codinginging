⚙️ How Nginx Verifies the Client Certificate

# nginx.conf relevant directives
ssl_client_certificate /etc/nginx/certs/ca/ca.crt;  # trust anchor
ssl_verify_client      on;                            # require client cert
ssl_verify_depth       2;                             # max chain depth

# After handshake, these variables are populated:
$ssl_client_verify     # → SUCCESS | FAILED | NONE
$ssl_client_s_dn       # → CN=demo-client,O=mTLS Demo,...
$ssl_client_i_dn       # → CN=mTLS Demo Root CA,...
$ssl_client_serial     # → hex serial number
$ssl_client_fingerprint # → SHA1 fingerprint

Nginx performs the full X.509 certificate chain validation: signature check → expiry check → CA trust check → key usage check. Only on SUCCESS does it proceed to route the request.

📅 Certificate Lifecycle & Rotation

  • The Root CA cert is valid 10 years. Its private key should be stored offline (HSM or air-gapped) and used only to sign new certs.
  • The Server cert is valid 1 year. Nginx reloads it with nginx -s reload — no downtime. Automate with certbot or internal PKI tooling.
  • The Client cert is valid 1 year. To revoke a client, add its serial to a CRL (ssl_crl) or use OCSP stapling (ssl_stapling).
  • Certificate rotation in mTLS does NOT require changing application code — the TLS layer handles it transparently.
